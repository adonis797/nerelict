# 广告跳转与广告项：通用适配

针对一类很常见的播放场景，不绑定任何具体站点：

1. 点视频封面，**第一次点击跳到广告页**，返回后再点一次才出现播放器；
2. 页面顶部/列表前几项是**广告位视频**，真实入口被压在下面；
3. 广告页本身也带 `<video>`，会和我们抢自动接管。

三条都靠地址形态与交互时序判断，不写站点选择器，因此换站不用改代码。

---

## 1. 判断规则

### 1.1 广告地址（`lib/services/ad_filter.dart`）

| 档位 | 依据 | 用途 |
|---|---|---|
| **高置信** | 主机名命中已知广告网络（`doubleclick.net`、`googlesyndication.com`、`adsystem.com`、`exoclick.com`、`trafficjunky.net`、`propellerads.com` 等 40 余个后缀） | 可**自动回退**广告页；媒体不自动接管 |
| **中置信** | 路径**整段**命中广告词（`/ads/`、`/ad/`、`/preroll/`、`/adserver-01/`、`/vast3/`），或查询参数含 `vast` / `vpaid` | 只**标记 + 提示**，不劫持导航 |
| 不判 | 其余全部 | 正常播放与列项 |

判定细节：

- 主机用**后缀 + 点边界**匹配：`doubleclick.net.evil.example` 不算广告，
  `securepubads.g.doubleclick.net` 算；
- 路径按**段**比对，不做子串匹配，所以 `download.mp4`、`shadow.mp4`、
  `adapter/`、`audio.m3u8`、`road/1.ts`、`advertise/` 都不会被误伤；
- 带后缀的段只在**下一个字符不是字母**时才判（`preroll_720`、`vast3` 命中，
  `advertise` 不命中）；
- `blob:` / `data:` / 非法地址直接放行（它们本来就进不了播放链路）。

### 1.2 广告落地页

同一套规则作用在**页面地址**上。是否处理还取决于时序：导航必须发生在
**点击后 6 秒内**，才算「这次点击被带去广告页」。用户自己手动输入的地址、
收藏夹跳转都不会被判成广告跳转。

---

## 2. 广告跳转怎么处理

```
点击视频（pointerdown 开会话，Dart 记下点击时刻）
   ↓ 页面跳转
onPageStarted(newUrl)
   ├─ 不是广告页 → 清标记；若刚从广告页回来，提示「已从广告页返回，再点一次」
   └─ 是广告页 且 距点击 < 6s
        ├─ 高置信 → 500ms 后 canGoBack 则 goBack，提示「已自动跳过广告页」
        └─ 中置信 → 只提示「已跳过疑似广告（路径段 /ads/）」
   ↓ 回到原页
onPageStarted 原页 → _handled 清空、点击捕获脚本重新注入、自动接管重新武装
   ↓ 用户再点一次
第二次点击正常命中真实视频 → 浮层播放
```

关键点：

- **每个页面只自动回退一次**（`_autoSkippedAd`），避免广告页 → 原页 → 广告页的死循环；
- 回退用 `canGoBack()` 兜底，退无可退时只提示不动作；
- 返回后不需要重启 App、不需要手动清列表：`onPageStarted` 本来就会清空本页的
  已处理集合与嗅探结果，点击脚本也会重新注入；
- 中置信只提示不劫持：误判的代价只是多一句提示，不会把用户从正常页面弹回去。

---

## 3. 顶部广告项怎么过滤

三件事同时做，互相不冲突：

1. **自动接管跳过广告媒体**：`PlayerChannel` 命中的地址若判为广告，直接
   `_handled.add` 并提示一次「已跳过疑似广告（原因）」，不打开播放器——
   否则用户刚点完视频，画面会被广告顶掉；
2. **点击浮标跳过广告**：点击捕获命中的广告地址不弹「浮层视频已捕获」；
3. **列表折叠 + 沉底**：聚合时给广告项打 `suspectAd` 标记，
   列表默认**不显示**，筛选栏出现「疑似广告 N」按钮，点一下才展开；
   展示顺序由 `orderForDisplay()` 统一处理——真实条目在前、广告沉底，
   组内保持「新的在前」。只改顺序，不丢数据。

广告项在展开后仍然可播放、可下载（用户自己选的不拦），
条目副标题会写明判定依据，例如 `疑似广告 · 路径段 /preroll`。

## 4. 播放器侧健壮性

- 初始化本来就有「30 秒超时 + 失败重建一次控制器」的兜底（`VideoPlayerCore.create`）；
- 新增**运行期错误可见化**：初始化之后的错误（403、分片断开、解码失败）
  以前只表现为黑屏，现在显示「播放中断：<原因>」并给一个**重试**按钮；
- 重试会重建内核并重新探测，不重置播放进度记忆；
- 广告地址不会走到播放器（自动接管已拦），手动点列表里的广告项仍可播放。

## 5. 边界情况

| 情况 | 表现 | 处理 |
|---|---|---|
| 广告与正片**同域名**、只是路径不同 | 路径段判定命中，标记为广告 | 列表可见但折叠；自动接管仍会跳过——若正片确实放在 `/ad/` 下，用户点开列表手动播放即可 |
| 广告走**服务端插播**（SSAI），与正片同一个 m3u8 | 地址形态完全一样，无法区分 | 不处理；这类广告只能靠播放器侧的广告标记（`#EXT-X-CUE-OUT`），当前不做 |
| 广告是**原生卡片**，点了才请求媒体 | 请求落在点击窗口内 | 广告域名/路径命中即标记；未命中则和正片一样处理（宁漏不误杀） |
| **软跳转**：用 JS 改内容但不换 URL | `onPageStarted` 不触发 | 判不出来，交给点击捕获的正常流程 |
| 广告用 `target=_blank` 新窗口打开 | WebView 未开启多窗口，`window.open` 被静默丢弃 | 用户停留在原页，等于已经跳过 |
| 广告页跳走时**无历史可退** | `canGoBack()` 为 false | 只提示「已跳过疑似广告」，由用户手动返回 |
| 高置信域名但其实是**正经 CDN** | 例如某些地区把 `criteo.com` 当图片 CDN | 只影响自动回退那一次；媒体侧只是折叠，展开可见，不会丢 |
| 页面本身就在广告域名下 | 每次导航都判广告 | 只有「点击后 6 秒内」才触发，正常浏览不受影响 |

## 播放器被广告压住 / 点不准按钮

应用内播放器是 Flutter 浮层，网页自己的浮层广告**盖不到**它。真正会压上来的是两类东西：

1. **系统级 JS 对话框**（`alert` / `confirm` / `prompt`）——WebView 用系统窗口渲染，层级在 Flutter 之上，
   用户想点播放键，实际点到的是对话框，还会被拖走；
2. **`window.open` 广告弹窗**——部分机型上会接管前台。

### 播放期弹窗守卫

播放器打开时注入 `kPlaybackGuardJs`，接管 `window.open` / `alert` / `confirm` / `prompt` 四个出口：
`open` 返回 `null`（等价浏览器拦了弹窗）、`alert` 不弹、`confirm` 返回 `false`、`prompt` 返回 `null`。
**只动这四个**，不碰 `location`、不碰事件、不碰 DOM，页面渲染与播放不受影响。

播放器关闭或切走时立刻注入 `kPlaybackGuardRestoreJs` 原样还原——否则站点后面用 `window.open`
打开登录页这类正常功能会被弄坏。换页会重建 JS 上下文，`_inject()` 在播放器仍开着的补挂一次。
设置里有独立开关「播放时拦截网页弹窗」（默认开）。

已知边界：只在应用内播放时生效；页面自己用 `<iframe>` 或全屏 DOM 做的插屏，本来就压不到 Flutter 浮层；
Service Worker 里的 `clients.openWindow` 拦不住（不在页面上下文）。

### 触控目标与「点空」

点空一次就可能点到网页上的广告并跳走，所以触控目标按下限 44dp 统一：

| 过去 | 现在 |
|---|---|
| `VisualDensity.compact` 图标按钮，命中区 28~34dp | 固定 44×44dp，命中区等于视觉外框 |
| 倍速 / 画质 / 音轨 / 字幕胶囊只有 ~21dp 高 | 最小 44dp 高，横向 10dp 内边距 |
| 控制条是横向滚动列表，带一点位移的点击变成滚动、按钮收不到 tap | 换成单行 `Row`：播放三键定宽，右侧胶囊 `Flexible + FittedBox` 缩放，不滚动也不换行 |
| 锁定按钮 31dp、错误页「重试」按钮 ~24dp 高 | 均 ≥44dp |

一开始试过 `Wrap`（放不下才换行），但真实浮层里它的可用宽度会被上层约束压窄，
结果四个胶囊竖着排成一列、盖在画面中间（真机截图里很明显）。改回 `Row` +
`Flexible(FittedBox(scaleDown))` 后，窄屏只是把胶囊按比例缩一点，布局不会塌。

另外加了一个 **350ms 防误触窗口**：打开播放器的那串触摸事件如果落到刚弹出的浮层上，
会被屏蔽，避免「刚打开就被自己的手指点成暂停 / 把控制条点没」。

### 控制器显隐（既有行为，未改动）

控件只在**正在播放**时才 4 秒后自动隐藏；暂停、锁定状态下常驻，出错时常驻并显示重试。
查找代码时确认过这一点，所以这轮没有改它——真正导致「点不到」的是命中区太小、
横向滚动抢手势和系统弹窗盖层，不是自动隐藏。

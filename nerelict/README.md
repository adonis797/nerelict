# Nerelict

浏览网页 → 当前页浮层播放器 → 下载 / 一键转 MP4 / 应用内播放。Flutter + Android WebView。

> **用途边界**：本项目仅用于个人学习与技术研究，请只对自己拥有合法访问权限的内容使用，
> 并遵守来源网站的服务条款与适用法律；不提供绕过付费、鉴权或 DRM 保护的能力。
> 仓库根目录另有 `README.md` 与 MIT 许可证。

## 名字由来

`Nerelict` = `net` + `relic`（读音也接近 `derelict`）：把网页里散落、易逝的流媒体片段
打捞下来，变成可以长期保存的本地文件 —— 一份「网络遗物」。

> v0.4.12 找到真正的原因：**站点是按 TLS / HTTP 栈识别客户端的，不是按请求头**。
> 关掉「边下边播缓存」时 HLS 由 ExoPlayer 直连能播，一开缓存就改成 Dart 发请求、直接 403；
> 下载同样死在 Dart 上——前面几轮调头全是白费。
> 现在两条路都改走 Android 自己的栈：下载兜底加了原生 `HttpURLConnection`（与 ExoPlayer 同层），
> 播放代理失败会自动改直连重试并记住该 host，不再出现「开缓存就播不了」。
>
> v0.4.11 下载改走「已经跑通的那条客户端」：同一个地址、同样只剩 `UA` + `Referer`，
> 播放代理（`dart:io` 的 `HttpClient`）能取到，Dio 却一直 403——差异不在头，在客户端。
> 现在 Dio 失败后直接用代理同款 `HttpClient` 再取一次（清单与分片都是），不再为了追头反复试。
> 另外修了个一直没生效的诊断：`evaluateJavascript` 对 Promise 只会回 `{}`，
> 所以「页面内 fetch 返回了什么」从来没被记录下来，现在改成写进 `window.__nr` 再取。
>
> v0.4.10 代取会告诉我们「到底卡在哪」：除了请求数与轮数，还回传该域在 WebView 里一共有几份 Cookie、
> 以及页面内 `fetch` 的状态码与**正文开头**。这三样加起来能一次分开三种情况——
> 请求根本没发出去（CSP）、该域一份 Cookie 都没下发（验证没走完）、下发了但请求没带上（头被裁）。
> 光看 `403` 是分不出「防盗链」和「人机验证」的。
>
> v0.4.9 下载侧再对齐一步：所谓「精简模式」其实没精简干净——Dio 的 `BaseOptions` 里还留着一个
> `Accept: */*`，会合并进每个请求，而播放代理从不发它，站点一眼就能分出两个客户端。现在精简模式
> 真的只剩 `User-Agent` + `Referer`。同时 WebView 代取改成每 2 秒重试一次 `fetch`（人机验证常是
> 「先给挑战页、几秒后自动跳回」，只发一次正好撞在挑战页上），失败提示里直接写出「实际发了哪些头」
> 与「代取试了几轮」，跨域时不再笼统让人「去取凭证」——试过什么、卡在哪，话里都有。
>
> v0.4.8 修一个自己造成的回归：0.4.6 为了让下载「更像浏览器」，把 `Sec-Fetch-*` / `Accept-Language`
> 也加到了**播放代理**上。下载侧至今没因此变好，但本来能播的 HLS 站点被这套多余的头打回 403。
> 现在播放恢复成最小身份（`User-Agent` + `Referer` + `Cookie` + 页面带来的鉴权头），
> 浏览器特征头只留给下载器——那条路径本来就在被拒，加了最坏也不过是继续被拒。
>
> v0.4.7 文件页重做：从「一层平铺列表 + 类型 chips」改成系统文件管理器的结构——分类宫格 → 最近播放 → 全部文件。
> 宫格细分到八类（视频 / 图片 / 音频 / 文档 / 电子书 / 压缩包 / 安装包 / 其他），带实时计数，点一下即筛选；
> 全部文件为单列，行内一行元信息：`MP4 视频 · 11:59 · 720p · 80.3 MB · 今天 10:13`，
> 元数据按需补（原生 `MediaMetadataRetriever` 读时长与分辨率，按 `path + size + mtime` 缓存到本地），
> 不拖慢扫描。`.m3u8` / `.mpd` 单独认作清单：不显示时长与分辨率，改显示分片数、是否齐全、是否加密，
> 缺段直接标红——点下去会播不动的情况，提前在列表里就能看出来。
> 管理动作全部收进行尾 `⋮`（播放 / 转 MP4 / 信息 / 重命名 / 选择 / 删除），长按进多选、底部批量删除；
> 搜索与排序（更新时间 / 名称 / 大小 / 时长）在页内，标题栏只留搜索与 `⋮`。
> 视频不再单独做页面：点行直接用 Nerelict 播放器打开，播放失败由播放器自己报。
>
> v0.4.6 把「能播不能下」的鉴权问题拆开来看：一是 `cf_clearance` 这类凭证带 `HttpOnly`，
> `CookieManager.getCookie()` 读不到；二是回源请求只有 UA / Referer / Cookie，缺
> `Accept` / `Accept-Language` / `Sec-Fetch-*`，在站点眼里不像浏览器。这一版先做前两层：
> 403 的提示不再一律「Cookie 未取到」，而是分成「该域确实没有 Cookie」「与当前页面不同域」
> 「只有 HttpOnly」「带了 Cookie 仍被挑战」四种，每种给一句可执行的建议；
> 回源请求补上浏览器等效头（下载器与播放代理共用一份，ExoPlayer 直连不动）。
> 方案与取舍见 `nerelict/docs/download-auth-and-challenge.md`，第三层（用 WebView 上下文代取
> Cookie）留待诊断结果确认后再做。
>
> v0.4.5 登录入口不再被自己的防护弄死：不少站点点「登录」毫无反应，其实是三处出口被我们
> 自己堵上了——① 登录弹窗的透明外壳同时满足「fixed + 高 z-index + 铺满视口 + 背景透明 +
> 文字少」，被判成广告遮挡层，整层被加 `pointer-events: none`（该属性会继承，弹窗里所有
> 控件一起失效），还会把当次点击 `preventDefault` 掉；现在含 `form` / `input` / `select` /
> `textarea` / `dialog` / `aria-modal` 的层一律不动，已处理过的层也不再向父层扩散。
> ② `window.open` 以前是「点击后 1.5 秒内一律返回 null」，而登录、OAuth 弹窗正好都在这个
> 窗口里；现在只在「媒体正在播放」或「点击落在视频容器内」时才算广告弹窗。
> ③ 放行的 `window.open` 与 `<a target="_blank">` 也开不出新窗口——WebView 侧没有
> `onCreateWindow` 入口，请求会被静默丢弃；现在统一降级成同页跳转。
> 另加：`weixin://`、`mqqapi://`、`alipays://`、`openlogin://` 等登录深链不再被静默拦截，
> 改由系统拉起对应 App，起不来给一句人话提示。
>
> v0.4.4 请求头透传：一部分站点不用 Cookie 鉴权，而是靠 `Authorization: Bearer …` 或
> 自定义 `X-*` 头——页面里能播，Nerelict 只带 UA / Referer / Cookie，于是在播放器里 403。
> 现在包装 `fetch` 时读 `init.headers` / `Request.headers`，hook `XMLHttpRequest.setRequestHeader`
> 并在 `send` 时上报，按白名单（`Authorization`、`X-*`、`Origin`）挑头随嗅探结果带回；
> 首屏播放器常先被 performance 扫描发现（只有地址），之后才被网络 hook 命中，这里会在补报时
> 把头补上而不再新建一条；从 POST 响应体里捞到的地址也继承发起该请求的头。
> 播放走本地代理时，头只存在内存登记表里，URL 上只带 12 位地址摘要令牌，m3u8 里的分片与
> `#EXT-X-KEY` 沿用同一令牌，重写播放列表不会把鉴权丢掉；关闭缓存直连时同样交给 ExoPlayer。
> 下载任务随任务持久化这批头（否则重启续传会退化成匿名请求），回读磁盘时再次过白名单。
> `Cookie` / `Range` / `Referer` / `User-Agent` 由链路自己生成，明确排除；值超过 1024 字节或
> 含换行的头直接丢弃（防头注入，也避免带着半个 token 去 403）；日志只记头的数量，不记值。
> 资源列表里这类条目会标「已带鉴权头」，一眼能看出它为什么能播。

> v0.4.3 抓不到 / 播不了的补齐：`#EXT-X-MAP` 从「只认第一个」改为挂在分片上，
> 播放列表中段换 init（多段 MAP / 换编码 / 插播）与 `BYTERANGE` 形式都能正确拼接，
> fMP4 下载不再产出缺少 moov 的坏文件；只嗅探到分片的视频（MSE / `blob:`）可以直接播放——
> 用已收分片合成一份 VOD 播放列表交给本地代理，分片仍带 Cookie / Referer 边下边播，
> fMP4 分片组因缺 init 会明确提示下载而不是硬凑；包装 `fetch` / `XHR` 时读取响应体，
> 把只存在于 POST JSON 里的播放地址（`/api/play`、GraphQL）也捞出来（限 512KB、只扫文本类响应）；
> `.mpd` 交给 ExoPlayer 直接播放（插件自带 media3-dash 模块），下载则明确拒绝并说明原因；
> 播放失败不再甩 `PlatformException(... Source error, null, null)`，改为「视频源打不开（可能需要登录 /
> 防盗链、地址已过期，或格式不受支持）」等 10 类人话提示；控制条四个胶囊统一 50×44dp、
> 数字等宽，倍速文案整数也写 `1.0x`。完整清单见 `docs/unsniffable-and-fixes.md`。

| 功能 | 入口 | 默认 | 关闭后行为 |
|---|---|---|---|
| 自动接管网页视频 | 设置 → 自动接管网页视频 | 开 | 视频继续在网页内播放，仅保留原有嗅探 |
| 点击捕获浮层视频 | 设置 → 点击捕获浮层视频 | 开 | 只嗅探页面加载时就发出的请求，「点开才加载」的播放器抓不到 |

| 疑似广告折叠 | 嗅探面板 → 疑似广告 N | 折叠 | 广告与正片混在一起排列 |
| 播放时拦截网页弹窗 | 设置 → 播放时拦截网页弹窗 | 开 | 播放中可能被网页 alert / 新窗口压住播放器 |
| 广告遮挡层清理 | 自动（点到透明整屏层时）/ 菜单 → 清理页面遮挡层 | 开 | 网页把广告层做成不透明整屏遮罩时不动它 |
| 浅色主题 | 设置 → 浅色主题 | 关（原深色） | 恢复原有深色主题 |
| 下载完成后自动转 MP4 | 设置 → 下载完成后自动转 MP4 | 开 | 保留 TS，可在「下载」页的 MP4 转换入口手动转换 |
| 谷歌快捷入口 | 首页「快速访问」 | — | 与原有 3 个入口并存 |
| 通知栏 / 锁屏媒体控制 | 设置 → 播放 / Nerelict 播放器 | 关 | 完全沿用原有播放方式，不申请音频焦点、不显示通知 |
| 自动续播 | 设置 → 播放 / Nerelict 播放器 | 开 | 每次从头播放，不读取进度记忆 |
| 画面手势 | 设置 → 播放 / Nerelict 播放器 | 开 | 画面只响应单击显示/隐藏控件 |
| 边下边播缓存 | 设置 → 播放 / Nerelict 播放器 | 关 | HLS 直接回源播放，不经过本地代理 |
| 默认倍速 | 设置 → 播放 / Nerelict 播放器 | 1x | 播放器内也可临时调整并记住 |
| 播放缓存上限 / 占用与清理 | 设置 → 播放 / Nerelict 播放器 | 256MB | 显示真实占用，可切换 64~1024MB 并一键清理 |
| 屏幕常亮 | 设置 → 屏幕常亮 | 开 | 交由系统息屏策略，长时间任务可能因休眠中断 |
| 应用内安装 APK | 设置 → 应用安装 | — | 静默不可用时回退系统安装器，需手动确认 |

- **Nerelict 播放器**：`video_player`（Android 底层 media3/ExoPlayer）原生支持 HLS m3u8 与 MP4，
  可传 Referer。检测到视频后先暂停网页内 `<video>`，再以浮层形式叠在**当前页面**之上自动播放，
  不 push 路由、不替换 body，网页滚动位置与浏览状态不中断；浮层内有醒目的「下载当前视频」按钮，
  右上角可随时关闭。嗅探横幅上的手动「播放」入口同样只打开浮层。
  每页每个地址只自动接管一次，关闭后 10 秒内不重复接管。
- **浏览历史**：页面加载完成时记录地址/标题/访问时间，首页「最近浏览」按时间倒序展示并可清空全部。
- **下载**：m3u8 走原有 HLS 解析/解密/合并链路；mp4 等直链视频走流式直链下载；
  每个任务可独立暂停/继续（保留已下载分片，续传用 Range），删除立即响应且不残留。
- **MP4 转换**：Android 原生 `MediaExtractor` + `MediaMuxer` 无重编码转封装
  （`android/app/src/main/kotlin/.../Mp4Converter.kt`），通过 MethodChannel 调用；
  只搬运 H.264/HEVC + AAC 样本，不重新编码、不引入 FFmpeg。转换后可直接在应用内播放产物。

### 播放器分层与边界（v3.3）

`media_detect`（现有 JS 通道） → `media_source`（归一化/请求头/类型探测） →
`player_core`（抽象接口，当前实现包住 `video_player`，Android 底层仍是 media3/ExoPlayer，
复用其 HLS/DASH/Progressive 解码与 video/audio track 选择） →
`player_ui`（浮层 / 全屏 / 迷你三态共用一个内核与一个 `PlayerPanel` 实例）；
`download_cache`（本地代理，默认关闭）与 `media_session`（MethodChannel + 原生）是两个可独立关闭的旁路。

菜单改为浮层内嵌面板，不使用 Navigator 弹窗，避免被「始终置顶」的浮层自己盖住。
UI 只依赖 `PlayerCore` 接口，将来替换成自研 Texture / PlatformView 内核不需要改 UI。

### 嗅探与接管怎么做的

`sniffer_js.dart` 在 `onPageStarted` / `onPageFinished` 时注入，三条互补路径：

1. 包装 `window.fetch` 和 `XMLHttpRequest.prototype.open` —— 页面自己发请求时立刻命中；
2. 每 2 秒扫 `performance.getEntriesByType('resource')` —— 兜住脚本注入之前就发出的请求；
3. 扫 `<video>/<source>` 的 src，以及页面地址本身（直接把 m3u8 地址当网页打开也能识别）。

命中后通过 `JavaScriptChannel('SniffChannel')` 回传，Dart 层去重后弹底部横幅。

`click_sniff_js.dart` 是第三条通道 `ClickChannel`，专治「视频要等用户点一下才存在」：

- 在捕获阶段旁路记录点击（`pointerdown` / `click`，全程 `passive`，不阻断页面交互），
  开一个 8 秒归因窗口；
- 窗口内的 `fetch` / `XHR` / 新增 `performance` 条目 / 新插入的 `<video>` / `play()` 调用
  都算到这次点击头上，连同点击目标描述一起上报；
- 给播放器容器打「浮层」分（`fixed`/`absolute` + 高 z-index + 覆盖面积 + 遮罩 + 弹窗类名 +
  点击后新插入），达到 50 分才标记「浮层播放」，普通内联播放器停在 30~45 不会误标；
- 拿到 m3u8 / 分片时并入同一份资源列表（被动嗅探先建好的项会原地补标记，不新增重复项）；
- 拿不到地址时按级降级：`performance` 差异 → 同源 iframe 直读 → 跨域 iframe 只给地址
  → MSE 提示并自动回扫 → 手动嗅探。判定规则与降级路径见 `docs/click-sniffing.md`。

广告与广告跳转的通用处理（不认站点，规则见 `docs/ad-playback-adaptation.md`）：

- 地址命中已知广告网络（`doubleclick.net`、`exoclick.com` 等）为**高置信**，
  命中 `/ads/`、`/preroll/`、`vast` 这类独占路径段为**中置信**，其余一律不判；
  路径按段比对，`download`、`shadow`、`adapter` 不会被误伤；
- 点击后 6 秒内跳到**高置信**广告页会在 500ms 后自动 `goBack`，
  中置信只提示不劫持；同一次跳转只回退一次，避免来回弹；
- 广告媒体不参与自动接管、不弹浮层浮标，避免刚点完视频就被广告顶掉画面；
- 嗅探列表默认折叠疑似广告（面板里有「疑似广告 N」可展开），
  展示顺序统一为「真实条目在前、广告沉底」；
- 播放器补上运行期错误提示（403 / 分片断开 / 解码失败不再是黑屏）与一键重试。

`player_probe_js.dart` 是独立的第二条通道 `PlayerChannel`：
m3u8 命中 fetch/XHR/performance/video/页面地址任一即可；mp4 等直链只认 `<video>/<source>`
和页面地址，避免广告视频误触发。两个脚本各自包一层 fetch/XHR/media src，
链式调用互不干扰。只放行 `http/https` 导航，拦掉 App 深链。

### 下载怎么做的

- 主播放列表先解析出全部码率档位：下载前可选定一档（记住上次选择；站点换列表时
  按分辨率回落，对不上才回落到最高档），任务卡片显示实际选中的档位；
- `#EXT-X-MEDIA` 的音轨 / 字幕组会被解析。音轨被拆成独立流的档位在选流面板里标注为
  不可选；若默认档位正好是这种，会自动退到第一个内置音轨的档位并在任务上写明原因，
  不再静默产出一个没有声音的文件；
- 出站请求带 `Referer`、`User-Agent` 与该站点在 WebView 里的 `Cookie`（登录态），
  Cookie 只在内存里按 host 缓存 90 秒，不落盘、不进日志；
- 支持 `#EXT-X-BYTERANGE`：同一文件的多个字节区间用 `Range` 分别请求，长度不符直接报错；
  `#EXT-X-DISCONTINUITY` 会被计数并在任务卡片与完成提示里说明时间轴有跳变；
- 分片并发 4 路；`AES-128` 用 `pointycastle` CBC + PKCS7 解密，未显式给 `IV` 时按分片序号推 16 字节大端 IV；
- 每个请求 45 秒整体超时（dio 的 `receiveTimeout` 只管两次数据之间，慢速滴流会一直挂着），超时后 `CancelToken` 取消并重试 3 次；
- 分片先落临时目录，全部完成后按顺序流式合并，避免内存峰值；
- 直链 mp4 流式落盘到临时文件，暂停后用 `Range` 从已下载字节续传；服务端不支持 Range 时自动从头重写；
- 暂停会中断在途请求但保留临时分片，删除任务会立即掐断请求并清理，各任务互不影响；
- 成品默认写入应用私有目录（无需存储权限）；若用户在「设置 → 下载位置」选了目录，
  会通过系统目录选择器（SAF）把成品再导出一份，应用内播放始终使用私有目录里的原件。

## 已知限制

- MP4 转换仅支持 H.264/HEVC + AAC 编码的 TS；其它编码（如 MPEG-2、AC3）会提示不支持，
  原 `.ts` 文件仍然可用。fMP4 分片本身输出就是 `.mp4`，不显示转换按钮。
- Service Worker、WebSocket 推流或 blob 地址的站点可能嗅探不到。
- 直播流（无 `#EXT-X-ENDLIST`）只下载当前列表里的分片。
- 音轨独立成流（`#EXT-X-MEDIA` 的 AUDIO 组带 `URI`）时无法与画面合并，只能改选内置音轨的档位；
  所有档位都音轨分离的视频当前无法下载。
- 字幕只做识别与展示，不随视频下载；`#EXT-X-DISCONTINUITY` 只做计数提示，不重写时间戳。
- release 包由本机 keystore 签名，未上传应用商店。
- 播放器：DRM（Widevine / ChinaDRM / SAMPLE-AES）、MSE/EME、`blob:` 地址、短时效签名 URL 不承诺支持；
  AV1、杜比视界、AC3/E-AC3 等编解码能力随设备而异；DASH 由系统解码器决定，未做专门适配。
- 投屏只提供系统投屏设置入口，未接入设备发现 / DLNA / Cast 协议；网络流无法截取纹理画面，
  截图只对本地文件可用（系统 `MediaMetadataRetriever` 取帧）。
- 未接入前台服务：应用切到后台时 `video_player` 会自动暂停、回前台自动恢复；通知栏控制与音频焦点
  用于前台/近期任务场景，长时间后台播放受厂商省电策略限制。系统画中画需 API 26+ 且设备支持。
- 边下边播缓存只缓存 HLS 分片的完整 GET 响应，带 Range 的请求直接回源转发；
  缓存与「下载完成导出」是两条独立路径。上限默认 256MB，可在设置里调整为 64~1024MB，
  设置页会显示真实占用并支持一键清理；启动时按生效上限裁剪旧分片。
